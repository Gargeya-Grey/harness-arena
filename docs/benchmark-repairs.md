# Audited benchmark repairs

This release repairs the case definitions, references, hidden checks, derived browser checks and shared scoring/measurement defects found in the complete 88-task audit. Human-time tiers remain unmeasured priors.

## Version boundaries

The previous suite versions remain frozen and loadable. The current suites are ladder-answer 3.0.0, ladder-code 3.0.0, ladder-agent 2.0.0, visual-web 1.1.0 and foldaway-apartment 1.2.0. Existing raw runs, scores and the evidence ledger retain their original bytes. Old experiments remain under experiments/archive/.

The recommended presets are `experiments/*-repaired-explicit-effort.yaml`. They request high effort explicitly on Beam, Haiku and Terra through their registered CLI harnesses. Requested effort is a provider-specific setting. Its runtime echo remains unknown when the CLI does not expose it. Dry-run checks dispatch configuration without using subscription quota. The repair proof does not claim a fresh model campaign or human timing study.

Use final-answer@2 for complete exact numeric scalars, js-function@3 for the repaired CPU/backstop policy and workspace-tests@3 for the repaired workspace policy and declared executable-test rules. Code and agent prompts are version 2. Historical evaluator implementations remain available; new policies do not change old scores.

## Correctness and time

Generation with timeout_s zero has no wall deadline. An explicit cutoff is incomplete execution. Code CPU/resource noncompliance, an incorrect returned value and an operational wall-clock stop are different outcomes. Function tests count loading plus call CPU. A backstop stop without established CPU noncompliance leaves the unfinished check unjudged. If another check has already proved a failure, the case scores zero as a proven case failure. The details retain the unfinished checks without treating them as wrong. Without a definite failure, an unresolved check prevents a case verdict and the scorer prints a skip reason.

The blocked log store now has one explicit batch-error, option-default and segment-read contract. Read-once recovery strategies are judged by the stated observable rule. The benchmark should not require one internal cache strategy.

Agent test requirements execute in a separate permission-restricted process under workspace-tests@3 when the hidden check declares them. A retained starter and a comment naming a method do not establish executable regression coverage. The task states its test requirements, and the check must distinguish real added tests from comment-only, empty and failing tests.

The executable-test driver streams confirmed test failures before completion, so a later backstop preserves an already failed assertion. It preserves actual default exports and observes a default alias of the tracked constructor. Modules preload through the test runner's asynchronous setup, retaining top-level await support. Cyclic tracked-module loading that cannot preserve observation is unjudged.

Call observation requires the public Node APIs `module.registerHooks` and `node:test.getTestContext`, verified on the installed Node 24.19.0. It binds required calls to the named added test file and observes mutable prototype calls as well as instance calls. An unsupported runtime, an immutable instance method or unobserved frozen prototype access is unjudged infrastructure. This avoids a false failure or vacuous test credit. The instrumentation is not claimed as a security boundary against arbitrary module-hook tampering.

## Difficulty

The three short-certificate instances are retired rather than repurposed. New case IDs occupy the same tier slots, preserve quotas and have independently checked expected values and nonzero gaps for the named cheap certificates. These checks do not establish a measured expert time or rule out every other shortcut. Human timing must match the task's allowed tools. Time to a final answer and time to an optimality certificate are recorded separately.

Sibling instances and related algorithm/apartment tasks are correlated. They do not constitute independent replications of general ability. A small pilot compares complete configurations, and does not establish reliability or a model-only ranking.

## Measurement and browser evidence

Claude multi-result accounting preserves the primary response and distinguishes summed episode counters from the final provider cumulative counters. Post-primary errors remain visible. Codex instructions respect no-tools prompts; accepted setup-isolation limits remain recorded.

Browser observation version 2 uses passed:null for blocked or incomplete checks. Summary failure counts include judged failures only. Inspectors wait for permitted geometry transitions, require effective visibility and camera framing, exercise both clamp directions/axes and configurator choices, sample guided movement, and check reversible retargeting atomically. Automated behavior checks do not certify visual design quality or continuous collision freedom.

The task-local repair report records exact red/green checks, full-suite/CLI/browser outcomes, independent review, preserved hashes and any remaining limits. No old model artifact is edited to improve its score.

Mutation audits run declared executable-test rules through the new workspace checker. They exclude unjudged verification. Reference fixtures describe the current solution; a current reference that no longer satisfies a frozen task is explicitly excluded from that old mutation audit. This does not prevent scoring old model runs against their frozen inputs.
