# Discover tests and manage history

Use only an owned disposable root from the launch recipe. Model calls are unnecessary. Keep before/after captures under the task evidence folder.

1. Open Home with no stored runs. Verify that the available active test families and the first-run guide are visible. Open each family and read a task. Check `/api/catalog`: public text and estimated tiers are present; expected answers and hidden checks are absent.
2. Prepare one call. Verify one included model, one case, and one repeat. Choose a supported thinking effort on that row. Add another setup with a different effort. Preview and inspect its command and output. Verify that the results directory has no new run. Clear setups to disable Preview and Start.
3. With fixture evidence, open Results and select harness and effort filters. Select Graphs, Outputs, and Runs. Verify the selected setup letters stay stable. Open an output and inspect the artifact URL and sandbox policy. Use keyboard navigation on every native select in light and dark at390px and1440px.
4. Follow Rerun. Verify that its selected models, harness, cases, repeats, and explicit effort match its source. It prepares only; no job starts. A deleted source or unavailable historical selection shows a reason and never selects all models or tasks.
5. In Results, delete one fixture run. Cancel first and verify unchanged storage. Submit a wrong confirmation through the API and verify400. Hold a store lock or run a stand-in job and verify refusal. Confirm the exact ID, then verify that only that run disappears and unrelated evidence remains trusted. Refresh and verify that a removed context shows no stale verdict or chart.
6. In Lab, inspect Storage. Confirm paths and run count. Type DELETE ALL RUNS and submit. Verify zero runs, contexts, observations, ratings, saved views, and finished jobs. Verify an empty ledger remains and source case bytes are unchanged. Run `node lab validate` against the disposable root.
7. Run `node --test tests/dashboard-history.test.mjs tests/dashboard-effort.test.mjs tests/dashboard-run-flow.test.mjs tests/effort-cli.test.mjs tests/storage.test.mjs tests/dashboard-history-browser.test.mjs`. These include a real stand-in CLI effort argument, saved metadata, confirmed CLI deletion/reset, traversal refusal, partial failure, and concurrent history writer checks. Browser regression checks invalidate old evidence after successful or partial deletion even when every refresh fails. Deleting the only selected setup must keep an explicit empty selection and offer Choose setups. They make no live provider call.

Close the browser and server you opened. Delete the owned disposable root after its final check. Preserve screenshots, transcripts, and measured cleanup receipts. A one-time owner reset is not ongoing deletion authority.
